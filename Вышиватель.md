# Вышиватель 0.1

Экспериментальная прошивка для платы BSMCE04U-PP / USB MACH3 на STM32F103, основанная на Mash3_grbl, коммит d491d156e76c8ae3c8b584b6e3bf8c04e161f549. Управляет пяльцами X/Y и швейным сервоприводом вместо педали. Прошла сборку и программные проверки; электрические параметры и движение реального аппарата пока не проверены.

## Файлы

- `Firmware/Vyshivatel-0.1-manual.hex` — скорость задаётся командой S.
- `Firmware/Vyshivatel-0.1-auto.hex` — скорость определяется длиной следующего стежка.
- `Firmware/Mash3_grbl.hex` — исходная CNC-прошивка, не версия «Вышиватель».
- `examples/embroidery.ngc` — небольшая программа для проверки последовательности.

Запись на плату автоматически не выполняется. Из конфигурации CubeIDE удалён исходный post-build, который прошивал плату сразу после сборки.

## Управление приводом

После запуска аппаратного PWM нейтраль всегда составляет 50%. M5, сброс и выключение шпинделя возвращают нейтраль. Параметр `$8` закреплён на 50: другие значения отвергаются. Существующие настройки шагов, скоростей и ускорений осей сохраняются. При загрузке старых настроек отключаются CNC-режим лазера и прежний Resume через PROBE. `$7=1` и `$32=1` недоступны.

В этой версии S означает заполнение PWM в промилле: `M3 S650` задаёт 65%. `$30` и `$31` не калибруют это соответствие. Ненулевой S ограничивается диапазоном 580–860, то есть 58–86%; коррекция скорости шпинделя также ограничена этим диапазоном. S0 возвращает нейтраль. M4 не поддерживается.

M6 и M30 запрашивают 40% на 1000 мс, затем 50%. Значение 40% выбрано по уточнению пользователя, хотя таблица исходного задания относит обрезку к другому диапазону напряжений. Соответствие этой команды фактической обрезке необходимо проверить на приводе. Если предыдущий XY-стежок завершён, прошивка сначала ожидает его следующий цикл иглы 1→0, чтобы дать машине выполнить последний прокол.

M6 после обрезки выдаёт сообщение о смене нити и обычную паузу оператора. Продолжение — командой Cycle Start / `~`. После неё программа должна снова задать M3 S… . M30 завершает программу. Сброс или Feed Hold во время обрезки отменяет импульс и возвращает нейтраль; пауза не растягивает импульс обрезки.

## Датчик и движение

Вход IN4/PROBE, PB15, зарезервирован для иглы. Активный логический сигнал PROBE означает «игла в ткани». Полярность на выводе PB15 задаётся `$6`: при `$6=1` высокий уровень означает иглу в ткани, при `$6=0` — низкий. Это позволяет учесть инверсию входного оптокаскада. Перед движением проверить, что в отчёте `?` поле `Pn:P` появляется именно при игле в ткани.

При активном датчике прерывание TIM2 выходит до выдачи нового импульса и до изменения счётчиков движения. Уже начавшийся импульс заканчивается штатно через TIM3. После снятия активного сигнала продолжается остаток того же перемещения; следующий стежок не подменяет незавершённый. Блокировка действует также на G0, Jog и поиск нуля.

Для G1 с включённым M3 прошивка ждёт наблюдаемый цикл 1→0 и выполняет ровно один блок XY с полной остановкой в его конце. Следующий блок ждёт нового цикла. Разрешения не накапливаются. Нулевая строка, не меняющая положение в шагах, пропускается без цикла иглы.

Ожидание между стежками отображается как `Hold:0`; это отдельное состояние синхронизации, не стандартный Feed Hold GRBL. Внутренне контроллер остаётся Idle, чтобы принимать следующие строки, M6 и M30. Команда `~` не заменяет цикл датчика. Пауза `!` и M0 используют штатное состояние HOLD и требуют команды оператора; датчик не снимает их. PWM между стежками сохраняется.

G0 и Jog выполняются при нейтрали привода. После G0 следующий G1 с модальным M3 вновь включает заданную скорость. G1 после M5 можно использовать для обычного перемещения при поднятой игле. Поддерживаются только линейные стежки X/Y: дуги, измерение щупом и команды осей Z/A отвергаются. Поиск нуля выполняется только по X/Y.

Строки стежков выполняются последовательно; подтверждение `ok` приходит после завершения XY-движения. Реальные задержки USB/ioSender и достаточность окна между проколами требуют стендовой проверки. Если XY не успевает до входа иглы в ткань, движение замораживается и продолжается в следующем окне; это защита от командных шагов при опущенной игле, а не гарантия качества стежка или отсутствия механического выбега. Частоту шитья нужно согласовать со скоростью и ускорениями пялец.

## Автоматическая скорость

Сборка auto сохраняет команду M3 как разрешение шитья и заменяет S для каждого ненулевого стежка. Для d² = dx² + dy² применяется:

```text
d² <= 4:    PWM = 860
d² >= 144:  PWM = 650
иначе:     PWM = 860 - 210 * (d² - 4) / 140
```

Результат округляется вниз до целых промилле. Это интерполяция по квадрату длины, без корня; она не является линейной интерполяцией по самой длине. Скорость устанавливается до ожидания разрешающего цикла датчика. В сборке manual действует S из программы.

## Сборка и программная проверка

Из папки firmware:

```powershell
.\build.ps1
.\build.ps1 -AutoSpeed
# При другом расположении компилятора:
.\build.ps1 -ToolchainBin 'C:\path\to\tools\bin'
python -m pip install unicorn pyelftools
python tests/test_firmware.py
python tests/test_firmware.py build/auto/Vyshivatel.elf
```

Скрипт использует GNU ARM из STM32CubeIDE и создаёт ELF, HEX и карту в `build/manual` либо `build/auto`. Запись прошивки на плату — отдельная операция. Эмулятор исполняет функции из собранного ELF; GPIO и время моделируются, транспорт USB, планировщик на границах теста и обслуживание realtime заменены тестовым окружением. Проверки не заменяют испытаний реального тайминга.

Проверены нейтраль, новый цикл на каждый стежок, независимость паузы оператора, неизменность счётчиков при заблокированном ISR, обрезка и её прерывание, последний цикл иглы перед обрезкой, границы S, запуск одного блока после датчика, G0/Jog без вращения и запрет неподдерживаемых команд. В auto дополнительно проверены границы и монотонность зависимости скорости.

## Проверка на стенде

1. Без подключения управляющего входа сервопривода измерить PWM и аналоговый сигнал: запуск, M5 и сброс — 50%, M3 S650 — 65%, M6/M30 — 40% на секунду, затем 50%. Питание выходного оптокаскада предполагается 5 В; реальные уровни на входе привода следует измерить. Прошивка не устанавливает напряжение питания внешнего каскада.
2. Проверить вход IN4 и подобрать `$6`: при игле в ткани отчёт `?` должен показывать `Pn:P`, при поднятой игле P должен отсутствовать. Уровень на внешней клемме нельзя отождествлять с уровнем на выводе MCU после опторазвязки.
3. При отключённых приводах XY проверить импульсы: при активном датчике новых шагов нет; G0/Jog при неактивном разрешены; каждый G1 после M3 требует отдельного цикла. Проверить активный сигнал в середине движения и сохранение конечной координаты после продолжения.
4. Проверить `!`/`~`, M0, M6, M30 и Ctrl-X, включая паузу и сброс во время обрезки; проверить непрерывную передачу нескольких G1 из ioSender.
5. После проверки сигналов испытать механику на низкой скорости, затем подобрать ускорения, подачу и скорость шитья.

Нейтраль до запуска PWM, во время аппаратного сброса, при отсутствии питания MCU и при зависании прошивки определяется аппаратной схемой. Требование 2,5 В уже в момент включения сервопривода необходимо обеспечить схемой или порядком включения питания. Контроль обрыва нити и сигнал окончания пока не реализованы.
