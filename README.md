# Embroiderer GRBL

**«Вышиватель» — специализированная прошивка GRBL для швейного аппарата с пяльцами, перемещаемыми по X/Y.** Контроллер управляет двумя шаговыми приводами и задаёт скорость швейного сервомотора через PWM вместо штатной педали. Датчик положения иглы разрешает отдельные стежки и блокирует новые шаги, пока игла находится в ткани.

Проект основан на [Mash3_grbl](https://github.com/abukarenko/Mash3_grbl), исходный коммит [`d491d15`](https://github.com/abukarenko/Mash3_grbl/commit/d491d156e76c8ae3c8b584b6e3bf8c04e161f549). История исходного проекта сохранена. Название **Embroiderer** переводится как «вышиватель».

**Текущий статус: экспериментальная версия 0.2.0.** Обе конфигурации собираются; выполнены проверки функций на ARM-эмуляторе. Исправлены проблемы, выявленные при практическом испытании 0.1; новую сборку требуется повторно проверить на аппарате. Измерено 2,8 В при PWM 50%; аналоговая коррекция пока не вводилась. Готовые HEX предназначены для этой проверки.

## Возможности

- Перемещение пялец по X/Y командами G0, G1 и Jog.
- Один ненулевой блок G1 на наблюдаемый цикл датчика иглы при включённом M3.
- Блокировка новых шаговых импульсов при игле в ткани, включая ручное движение и поиск нуля.
- Нейтраль привода 50% PWM после инициализации, при M5 и программном сбросе.
- Управление скоростью через `M3 S…` либо автоматический выбор по длине следующего стежка.
- M6: завершение последнего цикла иглы, команда обрезки, нейтраль и пауза на смену нити.
- M30: завершение последнего цикла иглы, команда обрезки и конец программы.
- USB CDC для связи с GRBL-совместимым отправителем G-code.
- TFT ILI9488 с сенсорным контроллером XPT2046, унаследованный от исходной прошивки.

|---|---|

| Память по linker script | Flash 254 КБ для программы, RAM 48 КБ |
| Основа протокола | GRBL 1.1f с изменённой логикой вышивки |
| Связь | USB CDC, виртуальный COM-порт; настройка отправителя 115200 бод |
| Рабочие оси | X/Y, координаты в миллиметрах при G21 |
| Скорость подачи | Миллиметры в минуту при G94 |

## Распиновка платы

### Шаговые приводы

| Сигнал | Обозначение канала платы | Вывод STM32 | Назначение |
|---|---|---|---|
| X STEP | X P | PB1 | Импульсы перемещения пялец по X |
| X DIR | X D | PB0 | Направление X |
| Y STEP | Y P | PC5 | Импульсы перемещения пялец по Y |
| Y DIR | Y D | PC4 | Направление Y |
| Разрешение буфера | Внутренний сигнал платы | PB10 | Общее управление выходным буфером; не отдельная команда швейному мотору |
| Z STEP / DIR | Z P / Z D | PA7 / PA6 | Унаследованный канал; команды Z в версии вышивки отвергаются |
| A STEP / DIR | A P / A D | PA5 / PA3 | Унаследованный канал; команды A в версии вышивки отвергаются |

Клеммы P/D подключаются к входам STEP/DIR внешних драйверов с учётом их схемы входов. Это сигнальные выходы, обмотки двигателей подключаются к драйверам. Общий провод и способ подключения входов драйвера выбираются по аппаратной схеме платы и драйвера.

### Клеммы IN/OUT и аналогового управления

Порядок клемм на изображённой плате — от OUT4 к 10V.

| Клемма | Вывод STM32 | Назначение в Embroiderer GRBL |
|---|---|---|
| OUT4 | PC9 | Унаследованный Mist; M7 в текущей конфигурации отключена |
| OUT3 | PC8 | Унаследованный Flood, M8/M9; функции вышивки не назначены |
| OUT2 | PC7 | Унаследованный выход направления; M4 не поддерживается |
| OUT1 | PC6 | Дискретное разрешение привода по логике spindle; отдельно от PWM |
| IN4 | PB15 | Датчик иглы, вместо измерительного щупа и прежнего Resume |
| IN3 | PB14 | Унаследованный концевик Z; продолжает учитываться общим контролем концевиков |
| IN2 | PB13 | Концевик Y |
| IN1 | PB12 | Концевик X |
| DCM | — | Общий провод внешних дискретных цепей IN/OUT |
| 24V | — | Питание внешней части дискретных цепей по схеме платы |
| ACM | — | Общий провод аналоговой части |
| AVI | PA8 через каскад платы | Аналоговый выход задания вместо сигнала педали |
| 10V | — | Вход опорного питания аналогового каскада, название унаследовано от CNC |

В исходном проекте аналоговая часть описана как 0–10 В при опорном питании 10 В. Для этого аппарата предполагается питание выходного оптокаскада от 5 В. Поэтому 50% PWM **ожидаются** как 2,5 В на управляющем входе сервопривода, но это соответствие ещё нужно измерить. Название клеммы 10V само по себе не подтверждает линейность конкретного каскада при питании 5 В.

`ACM`, `DCM` и логический `GND` относятся к разным частям платы. Их соединения определяются аппаратной схемой и требуемой развязкой. Напряжение внешних клемм нельзя переносить непосредственно на выводы STM32.

### Дискретные входы и выходы

В исходной схеме платы концевик или сухой контакт подключается между IN и DCM. Датчик с питаемым выходом подключают через совместимый входной каскад; его питание и допустимые уровни следует проверить для своей ревизии платы. Пять вольт питания PWM-каскада не задают допустимое напряжение непосредственно на PB15.

OUT1–OUT4 в исходном описании платы — транзисторные выходы с открытым коллектором: они замыкают внешнюю нагрузку на DCM и сами не являются источником напряжения.

```text
Питание внешней цепи ── нагрузка / совместимый вход ── OUTn
Общий внешней цепи ───────────────────────────────── DCM
```

OUT1 и AVI — разные сигналы. Нейтраль 50% выдаётся независимо от выключенного OUT1; при команде обрезки OUT1 выключен. Если сервопривод требует отдельного разрешения RUN, это нужно учесть в схеме подключения и проверить отдельно.

## Управление швейным сервомотором

Сервомотор управляется через его вход педали. Саму штатную педаль для этого режима заменяет управляющий выход контроллера; прошивка не управляет силовыми фазами мотора.

```text
ПК с ioSender ── USB ── STM32 ── STEP/DIR ── драйверы X/Y ── пяльцы
                           │
                           └── PWM ── опто/аналоговый каскад ── вход педали сервопривода

Датчик положения иглы ── входной каскад IN4 ── PB15
```

### Значения PWM

В этой версии S означает **заполнение PWM в промилле**, а не измеренные обороты вала. `M3 S650` задаёт 65%; `$30` и `$31` не калибруют это соответствие.

| Состояние или команда | PWM | Ожидаемое напряжение при линейном выходе 0–5 В |
|---|---:|---:|
| Нейтраль после инициализации | 50% | 2,50 В |
| M5, S0, программный сброс | 50% | 2,50 В |
| Минимальное ненулевое задание | 58% | 2,90 В |
| M3 S650 | 65% | 3,25 В |
| Верхняя граница задания | 86% | 4,30 В |
| Обрезка по M6/M30 | 20% на 1000 мс, затем 50% | 1,00 В, затем 2,50 В |

Ненулевой S ограничивается диапазоном 580–860. Коррекция скорости шпинделя также ограничена этими границами. Нейтраль закреплена на 50%; менять её через `$8` нельзя.

**20% для обрезки установлены по результатам испытаний от 11 ноября 2026 года** вместо прежних 40%. Напряжения в таблице идеальные: на проверенной плате 50% дали 2,8 В. Для выбора программной компенсации либо внешнего каскада см. [калибровку PWM](PWM-CALIBRATION.md).

После M6 контроллер возвращает нейтраль и ждёт оператора в обычном HOLD. После смены нити нужно подать Cycle Start / `~`; далее программа вновь включает мотор командой M3 S… . M30 выполняет обрезку и завершает программу. Если перед ними был стежок, сначала ожидается его следующий цикл иглы, чтобы дать машине выполнить последний прокол.

Сброс или Feed Hold во время обрезки прерывает импульс и возвращает нейтраль. До запуска аппаратного PWM — например, при включении питания или аппаратном reset — уровень определяется внешней схемой. Требование нейтрали уже в момент включения сервопривода обеспечивается схемой или последовательностью питания.

### Автоматическая скорость

Предусмотрены две отдельные сборки:

| Сборка | Задание скорости |
|---|---|
| manual | Через S в программе |
| auto | По длине следующего ненулевого стежка; M3 остаётся разрешением шитья |

Для автоматической версии вычисляется `d² = dx² + dy²`:

```text
d² <= 4 мм²:     PWM = 860                       (86%)
d² >= 64 мм²:    PWM = 740                       (74%)
иначе:          PWM = 860 - 120 × (d² - 4) / 60
```

До 2 мм включительно задаётся 86%, от 8 мм — 74%. Между границами используется интерполяция по **квадрату длины**, без извлечения корня. Результат округляется вниз до целых промилле. Новое задание устанавливается до ожидания разрешающего цикла иглы; это не замкнутый регулятор фактических оборотов.

## Датчик положения иглы

Логическое состояние датчика:

| Состояние | Смысл | Движение |
|---|---|---|
| 1, активен | Игла в ткани | Новые шаговые импульсы запрещены |
| 0, неактивен | Игла над тканью | Обычное позиционирование разрешено; стежок требует наблюдаемого перехода 1→0 |

Полярность относительно вывода MCU задаётся `$6`:

| Настройка | Игла считается находящейся в ткани, когда PB15… |
|---|---|
| `$6=0` | Имеет низкий уровень |
| `$6=1` | Имеет высокий уровень |

Опторазвязка может инвертировать внешний сигнал. Настраивать нужно по результату: при игле в ткани команда `?` должна показывать букву `P` в поле `Pn:`, а при поднятой игле P должна исчезать.

Для шитья последовательность следующая:

1. Программа включает M3 и передаёт ненулевой G1 по X/Y.
2. Контроллер наблюдает активный датчик, затем его переход в неактивное состояние.
3. Выполняется один XY-блок с полной остановкой в конце.
4. Следующий блок ждёт нового цикла датчика. Разрешения не накапливаются.

Между стежками PWM сохраняется. Нулевая строка, не меняющая положение в шагах, не расходует цикл датчика.

При входе иглы в ткань посреди движения обработчик TIM2 прекращает выдачу новых импульсов до изменения счётчиков. TIM3 завершает уже начавшийся импульс. После освобождения датчика продолжается остаток **того же** перемещения.

### Ожидание стежка и пауза оператора

| Ситуация | Отображение | Как продолжается |
|---|---|---|
| Ожидание датчика между стежками | Hold:0 | По новому циклу иглы; `~` не заменяет датчик |
| Блокировка активным датчиком во время XY | Hold:0 | После освобождения датчика, остаток текущего блока |
| Feed Hold `!`, M0, пауза смены нити | Штатный HOLD GRBL | По команде оператора `~` / Cycle Start |
| ALARM | Alarm | После устранения причины и штатного снятия блокировки |

Ожидание стежка реализовано отдельно от штатного Feed Hold: внутренне контроллер может оставаться Idle, чтобы принять следующую строку, M6 или M30. Датчик не снимает паузу оператора. Проверка совместимости такого поведения с непрерывной передачей из ioSender входит в стендовые испытания.

### Подключение IDC

![Схема подключения TFT и XPT2046](Pictures/connect%20display.jpg)

Нумерацию IDC сверяйте с рисунком и фактической ориентацией разъёма. Монтажная схема относится к модулю из исходного проекта.

| Сигнал модуля | IDC | STM32 / питание | Назначение |
|---|---:|---|---|
| VCC | 1 | +5 В | Питание указанного модуля дисплея |
| GND | 2 | GND | Общий логической части |
| SCK + T_CLK | 3 | PB8 | Общая тактовая линия |
| SDI/MOSI + T_DIN | 4 | PB9 | Данные от MCU |
| TFT CS | 5 | PB6 | Выбор ILI9488 |
| DC/RS | 6 | PB7 | Данные / команда TFT |
| T_DO | 7 | PB4 | Данные XPT2046 в MCU |
| T_CS | 8 | PB3 | Выбор XPT2046 |
| RESET | 9 | PD2 | Сброс TFT |
| T_IRQ | 10 | PC12 | Сигнал касания, активный низкий |
| SDO/MISO дисплея | — | Не подключается | Не путать с T_DO сенсора |
| LED | — | +3,3 В в исходной схеме, от SWD | Подсветка указанного модуля; сверить схему своего дисплея |

PB3/PB4 освобождены от JTAG, интерфейс SWD сохраняется. Коэффициенты affine-калибровки сенсора заданы в [xpt2046.c](Core/Src/xpt2046.c); автоматического мастера калибровки в описанной сборке нет.

### Сенсорные кнопки

| Кнопка | Текущее действие |
|---|---|
| FLUID | Переключение унаследованного Flood / OUT3; функция вышивки не назначена |
| SPINDLE | M3/M5; в обычном HOLD — spindle-stop override; во время ожидания иглы или обрезки переключение блокируется |
| PAUSE / RESUME | Во время Run/Jog вызывает Feed Hold, в штатном HOLD отправляет Cycle Start |
| UNLOCK | Программный reset и последующее `$X` |

При отображаемом Hold:0 ожидания иглы внутреннее состояние может быть Idle, поэтому экранная PAUSE не эквивалентна `!` в этом состоянии. Для проверки паузы между стежками используйте realtime-команду отправителя. Экран и сенсор обслуживаются без открытого COM-порта, но приём файла G-code требует подключённого отправителя.

| `?` | Текущий статус и входы |
| `$$` / `$I` / `$G` | Настройки / информация о сборке / модальное состояние |
| `$H` | Поиск нуля X/Y, если включён `$22` и подключены концевики |
| `$X` | Снятие блокировки ALARM после устранения причины |

M4, дуги G2/G3, измерение G38.x и команды координат Z/A в этой версии отвергаются. Четырёхосевой формат некоторых отчётов сохранён для совместимости исходного кода.

### Настройки для аппарата

| Настройка | Назначение |
|---|---|
| `$0` | Длительность STEP, мкс; по требованиям драйвера |
| `$1` | Задержка отключения шаговых приводов |
| `$2`, `$3`, `$4` | Инверсия STEP, направлений и разрешения приводов |
| `$5` | Инверсия концевиков |
| `$6` | Полярность датчика иглы |
| `$7=0` | Прежний Resume через PROBE отключён; 1 недоступно |
| `$8=50` | Фиксированная нейтраль PWM; другие значения недоступны |
| `$20`, `$21`, `$22` | Программные лимиты, аппаратные концевики, поиск нуля |
| `$23`–`$27` | Направление и параметры поиска нуля |
| `$100`, `$101` | Шагов на миллиметр X/Y |
| `$110`, `$111` | Максимальная скорость X/Y, мм/мин |
| `$120`, `$121` | Ускорение X/Y, мм/с² |
| `$130`, `$131` | Рабочий ход X/Y, мм |
| `$30`, `$31` | Унаследованы, не задают соответствие S→PWM этой версии |
| `$32=0` | Лазерный режим отключён; 1 недоступно |

При загрузке существующей EEPROM сохраняется калибровка движения, а `$7`, `$8` и лазерный режим приводятся к конфигурации вышивки. Унаследованные настройки Z/A могут оставаться в `$$`. IN3 всё ещё участвует в общем контроле концевиков, хотя ось Z не используется.

Для ременной передачи ориентировочный расчёт:

```text
шагов/мм = (шагов двигателя за оборот × микрошаг × передаточное отношение)
           / (шаг ремня, мм × число зубьев шкива)
```

Конкретные значения подачи, ускорения и шагов/мм зависят от механики; параметры исходного CNC-проекта нельзя считать готовой калибровкой пялец.

## Пример программы

```gcode
G21 G90 G94
M5
G0 X0 Y0
M3 S650
G1 X1 Y0 F1000
G1 X1 Y1 F1000
G1 X0 Y1 F1000
M6
(Сменить нить и подать Cycle Start)
M3 S650
G1 X0 Y0 F1000
M30
```

Готовый файл: [examples/embroidery.ngc](examples/embroidery.ngc). Это пример последовательности, а не проверенный режим конкретной машины. F1000 показана согласно заданию; для первого движения выбирают меньшую подходящую подачу. В auto команда S не определяет скорость каждого стежка.

Перед запуском оператор вручную устанавливает пяльцы, задаёт рабочий ноль, опускает лапку и запускает файл. Например, `G92 X0 Y0` временно задаёт текущую точку как нулевую через смещение G92; при использовании постоянных рабочих систем координат нужно учитывать смещения G54 и G92.

## Первый запуск

1. Сохранить текущие настройки платы командой `$$`, если на ней уже работала другая прошивка.
2. До подключения входа педали измерить выход: запуск/M5/reset — 50%, M3 S650 в manual — 65%, M6/M30 без предшествующих стежков — 20% на секунду и возврат 50%. Проверить реальные напряжения при выбранном питании аналогового каскада.
3. Подключить датчик к IN4 через подходящий входной каскад. Проверить `?` и подобрать `$6`: игла в ткани — P присутствует, поднята — P отсутствует.
4. При отключённой механике проверить STEP X/Y: активный датчик блокирует новые импульсы, каждый G1 при M3 требует своего цикла. Проверить активный датчик в середине блока и конечную координату после продолжения.
5. Проверить `!`, `~`, Ctrl-X, M0, M6/M30 и отмену обрезки при паузе/сбросе.
6. Подключить механику, проверить направления и калибровку на коротких перемещениях с остановленным швейным приводом. При ALARM сначала устранить причину, затем выполнить штатное снятие блокировки.
7. Испытать короткий файл на небольшой скорости, проверить поток из ioSender и подобрать время перемещения пялец относительно цикла иглы.

Если G1 при M3 ждёт бесконечно, сначала проверить датчик и P в статусе. Постоянный неактивный сигнал не разрешает стежок: требуется наблюдаемый цикл. Если XY не движутся даже при G0/Jog, проверить, не считается ли датчик постоянно активным.

## Сборка и программные проверки

Исходный проект STM32CubeIDE сохранён. Для воспроизводимой сборки из PowerShell в корне репозитория:

```powershell
.\build.ps1
.\build.ps1 -AutoSpeed
# Если ARM GNU установлен в другом месте:
.\build.ps1 -ToolchainBin 'C:\path\to\tools\bin'
```

Скрипт ищет ARM GNU из STM32CubeIDE в `C:\ST\STM32CubeIDE_*`. Результат — `build/manual/Vyshivatel.elf`, `.hex`, `.map` или аналогичный каталог `build/auto`. Проверенные опубликованные HEX лежат отдельно в Firmware; обычная сборка их автоматически не заменяет.

Проверки исполняют функции из собранного Thumb ELF в Unicorn:

```powershell
python -m pip install -r tests/requirements.txt
python tests/test_firmware.py
python tests/test_firmware.py build/auto/Vyshivatel.elf
```

Результат версии 0.2.0: **19 успешных проверок manual** и **20 auto**. В manual один из 20 тестов пропущен, поскольку функция автоматической скорости не включена линкером. Дополнительно к проверкам нейтрали, датчика, пауз, обрезки и скорости проверяется реальный путь планировщик → подготовка сегментов → прерывания TIM2/TIM3: сохранение PWM 650/740/768/860, последовательные блоки, M30 и M6 после последнего XY-блока. Эти тесты воспроизводят усечение PWM на прежнем ELF и проходят на исправленном.

Эмулятор моделирует GPIO и время; realtime-обслуживание заменено тестовым окружением. Отдельные тесты используют подмену планировщика, а новые регрессионные проверки исполняют реальный планировщик и генератор шагов. Это не полная симуляция USB, электроники и механики. Подробности: [VALIDATION.md](VALIDATION.md).

## Ограничения

- Стежки планируются по одному, с полной остановкой между блоками. Задержки отправителя могут привести к дополнительным циклам иглы без перемещения.
- Если XY не успевает завершиться до следующего прокола, шаги замораживаются и остаток переносится в следующее разрешённое окно. Это не гарантирует качество стежка и не останавливает механический выбег пялец мгновенно.
- Скорость шитья, подача и ускорение XY должны быть согласованы на реальном аппарате. Обратной связи по фактической частоте вращения нет.
- Обрыв/зависание датчика отдельно не диагностируется: постоянно активный вход блокирует движение, постоянно неактивный не даёт нового разрешения на стежок. Датчик не является аппаратной цепью аварийного останова.
- Начальное напряжение до запуска PWM и поведение при потере питания MCU определяются внешней схемой.
- Контроль обрыва нити, сигнал окончания и отдельная команда подъёма лапки пока не реализованы.
- Интерфейс дисплея ещё содержит обозначения исходной CNC-прошивки.
